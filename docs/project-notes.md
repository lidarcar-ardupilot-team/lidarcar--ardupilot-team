# 项目复盘笔记

> **状态：待成员补写。** 这里保留第一次获奖过程中的选择、失误、协作、转折和感受。它是项目的个人/团队记忆，不替代源码、参数、视频或验收结论。

## 写作边界

- 可以写“当时如何理解问题、为什么换方案、谁帮了什么忙、哪些场景记得最深”；这些内容不必伪装成实验报告。
- 涉及代码版本、硬件变更、赛场成绩或性能数字时，链接到对应模块文档或 [项目资料与验证状态](evidence-and-status.md)；不确定的回忆明确标成“个人回忆”。
- 项目故事与技术结论分开：故事可以保留情绪和细节，技术结论仍遵守 `planned`、`bench-verified`、`field-verified`、`stage-record` 等状态标签。

## 建议从这些片段开始

不要求照此顺序写。可以从一个最鲜明的画面、一次翻车、一次深夜联调或领奖时刻开始，再补全前因后果。

1. **起点：** 当时为什么参加，最初的小车/任务设想是什么；
2. **第一次真正卡住：** 硬件、定位、控制、协作或赛场规则中最难的一关；
3. **转折：** 哪次测试、谁的一句话、哪个日志或哪次取舍改变了方向；
4. **协作：** 每个人如何把自己的部分接起来，哪里曾经交接失败，后来怎样解决；
5. **获奖现场：** 可以保留紧张、意外、遗憾和高兴，但不要把未核实的成绩细节写成技术数据；
6. **留下什么：** 后来仍在沿用的工作方式、最想提醒下一届队员的一件事。
