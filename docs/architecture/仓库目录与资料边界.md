# 仓库边界与协作规则

## 两条组织轴

仓库同时保留“负责人”和“证据/来源”两条组织轴，避免把历史源码的来源误认为当前职责：

| 对象 | 位置 | 规则 |
| --- | --- | --- |
| haimichenha 的雷达小车实现与说明 | `car/` | MSPM0、雷达、定位/规划、驱动、引脚和实车记录由该目录维护。 |
| 黄总的无人机实现与说明 | `aircraft/` | 飞控、机载通信、飞行状态与证据在该目录维护。 |
| 韦少的视觉与舵机投递实现与说明 | `vision/` | 视觉识别、模型发布、舵机投递接口与证据在该目录维护。 |
| 雷达小车 PCB、接线与板测 | `car/hardware/` | 以原理图、实物与板测为依据；不假定它与无人机或视觉硬件共用。 |

## 阶段材料进入当前实现的门槛

从阶段文件或后续引入的第三方代码取用内容时，提交中必须说明目标文件、当前目标、MSPM0G3507/PCB 接口差异和验证证据。只有文件内容、构建配置、硬件接口和目标场景均已核对时，才能作为当前实现的一部分；否则它只能作为阶段资料，不能作为实车结论。

跨端接口变更需要在受影响的负责人目录同时记录；职责目录之间不复制同一份可执行源码，以免版本和验证状态分叉。
