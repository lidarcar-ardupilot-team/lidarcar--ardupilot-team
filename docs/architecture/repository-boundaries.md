# 仓库边界与协作规则

## 两条组织轴

仓库同时保留“负责人”和“可复用基线”两条组织轴，避免把历史源码的来源误认为当前职责：

| 对象 | 位置 | 规则 |
| --- | --- | --- |
| haimichenha 的雷达小车实现与说明 | `car/` | MSPM0、雷达、定位/规划、驱动、引脚和实车记录由该目录维护。 |
| 黄总的无人机实现与说明 | `aircraft/` | 飞控、机载通信、飞行状态与证据在该目录维护。 |
| 韦少的视觉与舵机投递实现与说明 | `vision/` | 视觉识别、模型发布、舵机投递接口与证据在该目录维护。 |
| PCB、车架、电源、线束与板测 | `shared/` | 以原理图、实物与板测为依据。 |
| 既有 STM32 车端代码 | `reference/stm32f103zet6-vehicle-base/` | 可按需比较和改造；不直接继承原有参数、引脚或实测结论。 |

## 复用与改造门槛

从 `reference/` 取用代码时，提交中必须说明来源文件、当前目标、硬件接口差异和验证证据。只有文件内容、构建配置、硬件接口和目标场景均已核对时，才能作为当前实现的一部分；否则它始终是 `reference`，不能作为实车结论。

共享接口变更需要在受影响的负责人目录同时记录；职责目录之间不复制同一份可执行源码，以免版本和验证状态分叉。
