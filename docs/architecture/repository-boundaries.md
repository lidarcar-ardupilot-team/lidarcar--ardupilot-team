# 仓库边界与共享规则

## 为什么按赛事分轨

两项赛事使用相同团队和 PCB，并不产生相同的控制问题：电赛以 STM32 灰度循迹、任务按钮和空地协同为主；机器人赛归档以 MSPM0、雷达位姿和 A* 返航为主。两条轨道分别保存代码、参数、证据和回退点。

## 可共享与不可共享

| 对象 | 位置 | 规则 |
| --- | --- | --- |
| PCB、车架、电源、线束与板测 | `shared/` | 以原理图/实物/板测为依据 |
| 电赛 STM32 控制 | `projects/electrical-contest/` | 当前引脚、协议与赛道证据独立维护 |
| 机器人赛 MSPM0 雷达控制 | `projects/robot-ai-contest/` | 历史快照和后续验证独立维护 |
| 跨赛可复用方法 | 文档中明确标注 | 只复用方法，不自动复用参数或验收结论 |

## 提炼共享代码的门槛

只有在文件内容、构建配置、硬件接口和至少一项目标赛事实测均一致时，才可将代码提炼到共享层。否则采用复制来源加明确差异说明，避免“看起来相同”造成未验证耦合。
