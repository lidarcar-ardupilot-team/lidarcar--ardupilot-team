## 阅读顺序

1. 新加入或跨模块开发：先读 [团队职责与接口](团队分工与接口约定.md)；
2. 准备引用某张照片、日志、视频或旧代码：再读 [资料与证据索引](项目资料与验证状态.md)；
3. 落地到具体模块时，进入负责人目录，记录构建、硬件版本、测试条件和结论；
4. 要复用阶段文件时，最后检查 [阶段材料进入当前实现的门槛](architecture/仓库目录与资料边界.md#阶段材料进入当前实现的门槛)。

开发过程较长时，在对应模块中保留阶段版本、测试条件和结论；公共文档只保留能帮助当前协作的接口、规则与索引，避免把所有调试流水堆入一个 README。

## 维护边界

- 新增的公共规则、接口合同、共同硬件事实和全队时间线放在本目录；
- 单人负责的代码、调参、硬件接口和证据不要复制到这里；在本目录放一个链接即可；
- 任何 `field-verified` 结论都要能回到负责人的固件版本、场地条件和原始证据。
