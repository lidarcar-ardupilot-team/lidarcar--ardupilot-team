# 团队资料入口

本目录只放赛题公共说明、跨模块接口、验证状态和项目复盘。具体实现、参数和测试记录仍放进 [`../car/`](../car/)、[`../aircraft/`](../aircraft/) 或 [`../vision/`](../vision/)。

## 按目的阅读

| 目的 | 文档 | 用途 |
| --- | --- | --- |
| 先了解谁负责什么、怎么交接 | [团队职责与接口](team-collaboration.md) | 三人边界、跨模块交接模板和变更顺序。 |
| 判断已有材料能证明什么 | [项目资料与验证状态](evidence-and-status.md) | 验证等级、现有材料与禁止泛化的边界。 |
| 判断文件应放在哪 | [仓库边界与协作规则](architecture/repository-boundaries.md) | 职责目录、共享目录与历史资料的分界。 |
| 查赛题、场地与评分 | [低空无人机智慧救援](competition/) | 官方任务闭环、场地尺寸、评分矩阵和材料入口。 |
| 阅读项目经历而非技术说明 | [项目复盘笔记](project-notes.md) | 个人复盘与团队经历；不作为性能或验收证据。 |
| 检查雷达小车的 PCB 与接线 | [小车硬件入口](../car/hardware/) | 原理图、版本与板测材料。 |

## 阅读顺序

1. 新加入或跨模块开发：先读 [团队职责与接口](team-collaboration.md)；
2. 准备引用某张照片、日志、视频或旧代码：再读 [资料与证据索引](evidence-and-status.md)；
3. 落地到具体模块时，进入负责人目录，记录构建、硬件版本、测试条件和结论；
4. 要复用阶段文件时，最后检查 [阶段材料进入当前实现的门槛](architecture/repository-boundaries.md#阶段材料进入当前实现的门槛)。

开发过程较长时，在对应模块中保留阶段版本、测试条件和结论；公共文档只保留能帮助当前协作的接口、规则与索引，避免把所有调试流水堆入一个 README。

## 维护边界

- 新增的公共规则、接口合同、共同硬件事实和全队时间线放在本目录；
- 单人负责的代码、调参、硬件接口和证据不要复制到这里；在本目录放一个链接即可；
- 任何 `field-verified` 结论都要能回到负责人的固件版本、场地条件和原始证据。
