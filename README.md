本仓库按**系统分工**组织协作资料。三人共用 PCB、车辆平台和必要的接口记录；每个负责人只在自己的目录维护职责范围内的代码、说明和验证证据。

## 协同边界

- 小车目录维护本地定位、规划、驱动和停车等车端安全判断；无人机状态或视觉结果只能通过明确记录的接口参与协同。
- 无人机目录维护飞控、飞行与机载通信；投递动作和视觉结果的消费条件须与 `vision/` 同步记录。
- 视觉目录维护识别与舵机投递；它只输出经验证的结果或触发条件，不替代飞控状态机和小车本地安全逻辑。

## 目录规则

1. `car/`、`aircraft/`、`vision/` 分别放三位负责人的说明、计划、验证记录和正式代码；跨职责改动先在相关目录留下接口记录。
2. `shared/` 只放所有人确实共用的硬件事实、PCB 版本和安全上电流程，不放控制参数或路线结论。
3. `reference/` 是可阅读、比较和**按需改造**的已有源码基线；其中的引脚、协议、阈值和验收结果不会自动继承到当前小车。
4. 每个验证结论标注为 `planned`、`bench-verified`、`field-verified` 或 `reference`。构建通过不等于实车通过。
5. 构建目录、烧录产物、日志、模型权重、凭据和 IDE 私有状态不得提交。

当前已迁入的雷达小车控制器是可追溯的 MSPM0 `empty.c` 历史快照；完整工程、PCB 源文件和其他职责的正式实现待负责人补充。新增或修改硬件、引脚或控制策略前，先更新相应负责人目录中的说明与证据，再提交代码。
