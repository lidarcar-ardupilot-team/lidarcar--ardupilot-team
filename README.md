## 团队职责与协同

- **小车**负责车体定位、规划、底盘驱动与本地停车等安全判断；不能把无人机或视觉消息直接当作车端安全结论。
- **无人机**负责飞控、机载通信、飞行阶段与飞行验证；飞控逻辑不由小车或视觉目录单方面修改。
- **视觉与投递**负责识别、结果接口、舵机投递及其验证；它输出经过定义的结果或触发条件，不替代飞控状态机。
- **共用硬件**负责 PCB、车架、供电、线束与安全上电事实；具体速度、路径、阈值和控制参数仍归各负责人目录。

跨模块的消息、坐标、触发条件或硬件接口变更，先按 [团队职责与接口](docs/team-collaboration.md) 补齐交接记录，再分别更新受影响目录；不要把同一份可执行代码复制到多个职责目录。

## 仓库规则

1. **先定位，再修改。** 从本页进入对应模块；对小车历史文件先读 [来源与完整性边界](provenance/SOURCES.md)。
2. **先证据，后结论。** 构建通过、单张照片或单段视频不能泛化为全车/全任务通过。每条结论带状态、版本、条件与证据路径。
3. **参考不等于现役。** `reference/` 的引脚、协议、速度和结果只有在目标硬件、构建和实测都完成核对后，才可迁入负责人的正式目录。
4. **共用事实只记一处。** PCB、车架、供电和上电规则进入 `shared/`；代码、参数、路线和任务逻辑留在负责人目录。
5. 提交前执行 [协作与变更规则](CONTRIBUTING.md) 中的最小检查；不提交构建产物、凭据、模型权重、原始大视频、运行日志或 IDE 私有状态。
