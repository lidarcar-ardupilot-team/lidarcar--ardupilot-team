# 雷达小车开发工作流

**状态：项目执行规范。** 本文定义本仓库小车端从硬件核对到现场联调的层级、证据和回退规则。它不是调试流水账；每轮只记录对当前工程有用的结论和材料。

当前仓库包含阶段性的 `empty.c` 控制文件，但不含完整 MSPM0 工程和版本化 `*.syscfg`。因此，下面规则用于恢复或新建工程时的执行顺序，不能把阶段参数直接视为当前实测结论。

## 每轮任务先写清

```text
当前目标：
对应需求 / 通过门槛：
本轮只验证的层：硬件 / 日志 / 位姿 / 坐标 / 规划 / 控制 / 禁区 / 串联
最小测试链路：
必看日志字段：
停止条件：
回退点 / checkpoint：
```

无法说明“对应需求或通过门槛”时，先回到规则、场地或接口核对，不进入参数调整。

## 分层执行顺序

| 层 | 目标 | 最小证据 | 禁止事项 |
| --- | --- | --- | --- |
| 硬件与 PinMux | 电源、驱动、传感器和无线接口可用 | 实物量测、版本化 `.syscfg`、生成配置 | 用旧代码或口头引脚表替代板测 |
| 日志链路 | 现场过程可重建 | 带时间、状态、位姿、指令和错误字段的记录 | 无日志时凭肉眼调参 |
| 位姿与坐标 | 位姿、目标和地图使用同一坐标系 | 新鲜度、有效位、坐标/航向误差与转换记录 | 用 MCU 偏置掩盖定位问题 |
| 规划与禁区 | 路径能到点且避开边界 | 实测禁区几何、膨胀参数、规划结果与停止原因 | 长期用假禁区或口头路线调试 |
| 速度与执行 | 轮子按目标可重复运动 | 编码器、左右命令、速度、航向和电机方向记录 | 用开环 PWM 偏置作为最终导航方案 |
| 串联验收 | 完成规定任务并可回退 | 需求清单、日志/视频、固件哈希和 checkpoint | 无备份的大改或跨层混改 |

每次只修改一个层。`empty.c` 仅承担入口与调度；可复用逻辑应拆到协议、日志、规划、速度环、硬件驱动等接口明确的模块中。

## 何时停止当前方向

出现任一情况立即停止本轮调参，并切换到可验证的替代动作：

1. 连续三轮没有可解释的日志改善。
2. 参数变化很大但结果随机，或现象更像接线、方向、坐标或架构问题。
3. 已有可用版本却没有 checkpoint。

| 卡点 | 优先替代动作 |
| --- | --- |
| 参数无改善 | 补足日志字段，先解释现象。 |
| 硬件异常 | 换线、换模块、换电源、测电压，缩小到最小链路。 |
| 位姿不稳 | 核对传感器输入、坐标转换和有效性；必要时替换或重建定位链路。 |
| 路线或禁区异常 | 回到实测几何、目标定义和规划输入，不继续微调速度。 |
| 知识或规则不确定 | 查官方资料、原始规则和历史证据，记录可复用结论。 |

## 日志底线与保存

每轮现场记录至少能回答：代码是谁、车在哪里、车要去哪里、为什么这样运动、为什么停止、是否触发边界保护、是否存在硬件或通信错误。推荐字段：

```text
tag, commit, time_ms, state,
pose_x, pose_y, yaw, valid, age,
target, route, waypoint, path_len,
cmd_l, cmd_r, speed_l, speed_r, encoder,
stop_src, protect, fault, plan_fail,
forbid_id, forbid_dist, rx, ok, err
```

达到可复用结论后，立即保存日志/视频索引、更新相应 Markdown，并创建 Git checkpoint。A/B 空地联调的阶段视频预览与文件哈希见 [`../evidence/20260710-airlink-ab-return/README.md`](../evidence/20260710-airlink-ab-return/README.md)。
